## NEW GAPS FOUND

### GAP-1: Thin server technology unspecified (MINOR)

The PRD specifies endpoints, HTTP methods, error format, and loopback binding. It does NOT specify: what language/runtime the server is written in (Node? Python?), where it lives in the repo, how to start it alongside the Vite dev server, or whether it reuses the existing `factory/metrics.py` logic. The package.json has no server-related scripts. The PRD references "factory/metrics.py harvest output" but doesn't connect it to the server implementation.

An engineer can choose a technology, but they're inventing that decision. Recommend: either (a) note "server technology TBD by implementer" in Assumptions, or (b) if the existing `metrics.py` is the natural host, say so and define a `server.py` entry point.

### GAP-2: Overhead ratio — aggregate vs per-story not disambiguated (MINOR)

The formula: `noncoder_tokens / coder_tokens (None when coder_tokens == 0)`. This works for per-story rows (each row has one coder_tokens value). For the headline card, "process-overhead ratio across the selected scope" could be:

- Aggregate: sum(noncoder) / sum(coder) → 0.841 for mock data
- Mean of per-story ratios: mean(0, 1.117, 0.579, 0.940, 1.377) → 0.803

The wireframe shows 0.94, which happens to be TOD-4's individual ratio — not matching either aggregate interpretation. An engineer reading the PRD would likely choose aggregate (matching "across the selected scope" language), but it's not explicit. Recommend: clarify "aggregate ratio (sum noncoder / sum coder across scope)."

### GAP-3: Trends component wireframe has no empty-state branch (MINOR)

PRD acceptance criteria for trend views: "empty scope shows a friendly empty state, not a blank axis." The ScopeSelector component has an empty state (`dash-empty`), and the story `factory-dashboard--scope-empty` covers it. But the Trends component always renders bars — it has no conditional branch for receiving zero stories. Since the wireframe doesn't wire scope through to child components, this doesn't surface, but a real implementation needs it. The PRD text covers it; the wireframe just doesn't demonstrate it.

Recommend: either add an empty-state guard in Trends (simple), or note in the PRD that empty-state rendering is delegated to the parent scope container — but right now the language says each view handles it.

### GAP-4: No loading state specified (MINOR)

The dashboard fetches from /api/runs, /api/ledger, and /api/findings. Between mount and data arrival there's a loading period. Neither the PRD nor the wireframes specify a loading state. The PRD covers error and empty states but skips loading. An engineer can add a spinner or skeleton, but it's a product decision: what does the dashboard look like while waiting? Recommend: add a 1-line note ("Loading state: subtle spinner or skeleton; implementation detail, no separate wireframe required.")

### GAP-5: FullDashboard wireframe doesn't demonstrate scope reactivity (MINOR)

FullDashboard (lines 148-164) renders Scope selector + HeadlineCards + StoryTable + Trends, but `scope` state is local to FullDashboard and never passed to child components. HeadlineCards, StoryTable, and Trends always render the full STORIES array. This is understandable for a wireframe (the data views receive no props), but it means the "all views react to scope" behavior from the PRD is not visually demonstrated. An engineer reading the PRD knows the intent; the wireframe just doesn't prove the interaction.

### GAP-6: Wireframe model-mix data diverges from STORIES data (COSMETIC)

The mock STORIES array only contains `qwen4-max-preview` stories (6 rows). The Trends model-mix section shows two rows: `qwen4-max-preview` (7.76M, 70%) and `deepseek-v4-pro` (3.32M, 30%). The second model doesn't appear in STORIES. Total tokens shown (~11.08M) also doesn't match the STORIES total (~11.08M — wait, let me check: 5,716,735 coder + 4,806,215 non + 2,625,505 control coder = 13,148,455 total. 7.76 + 3.32 = 11.08. Neither matches.). This is purely cosmetic for a wireframe, but a reviewer who traces the numbers will find inconsistency. Recommend: either align mock data or add a comment that the model mix is illustrative.

### GAP-7: Port number discrepancy (COSMETIC)

The PRD says "localhost:6007" but package.json scripts say `storybook dev -p 6006`. Both ports currently serve Storybook (6007 appears to be a separate static-file server, possibly `npx serve storybook-static -p 6007`). The PRD's URL works, so this is operational, but the port mismatch between source of truth (package.json) and documented URL (PRD) will confuse someone starting fresh. Recommend: align to one port.
